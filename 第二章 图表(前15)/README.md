matplotlib 的字形光栅化器不同，几何位置已经全部对齐。

## 文件说明

```
chartkit.py                公共部件：画布换算、字体、manualLayout、userShapes、量墨迹
export_reference.py        用 Excel COM 把 15 张图导出成比对基准（reference/）
inspect_chart_xml.py N     把 chartN.xml 压成可读的样式规格（--raw 看原始 XML）
inspect_usershapes.py N    列出图表 userShapes 里的标题/副标题/脚注/标注框
compare_reference.py N     与原图做像素级比对（--diff 时才落盘对照图）
chartN_*.py + .png         15 张图的脚本与输出
reference/
  chartN_excel.png         原图（Excel 导出，比对基准）
  chartN_meta.txt          图表对象的宽高/位置，用来核对画布大小
```

## 运行

```bash
pip install matplotlib numpy pillow pywin32

python export_reference.py          # 重新导出比对基准（需要装了 Excel）
python chart1_gradient_bar.py       # 生成 chart1_gradient_bar.png
python compare_reference.py 1       # 与原图比对
python inspect_chart_xml.py 5       # 看第 5 张图的样式规格
```

`pip install pywin32` 只在想重新导出原图时才需要；比对和渲染有 matplotlib +
numpy + pillow 就够了。

## 两图共用的换算

**字号换算系数是 1.44**。画布按 2 px/pt 还原 Excel 图表（416pt 宽的图表
导出成 832px），而坐标轴文字在 XML 里是 9pt，因此 matplotlib 字号
= 9 × 2 × 72/100 = 12.96pt。标题、副标题、脚注同理。

坐标轴与数据标签的拉丁字形继承主题字体（Calibri），中文继承工作簿默认
字体（等线 DengXian），脚本用 matplotlib 的字体回退列表
`["Calibri", "DengXian"]` 实现；标题/副标题/脚注在 XML 里显式写死了
微软雅黑，所以单独指定；而像图 14 圆心那种没指定字体的文本框，走的又是
主题字体，用微软雅黑会宽出 18%。

**文字位置一律实测，不靠算。** Excel 的文本行盒和 matplotlib 的基线规则
不一致，同一条基线在两者之间能差好几个像素，而且随字号变化没有统一公式。
所以脚本里所有文字落点都是先用 `chartkit.ink_bbox` 从原图上量出墨迹行/列
范围，再把自己的输出量到同一位置——每个这样的常数在注释里都标了「实测」。

## 十五张图各自的关键机关

### 图 1 · 渐变柱形图

**渐变作用在单根柱子上**，不是整个系列。每根柱子的渐变都铺满自身高度，所以
1902 那根矮柱的顶端颜色和 3524 那根高柱一样深，底端一样浅。若把渐变铺满
整个绘图区，矮柱会明显偏浅。

### 图 2 · 带均值柱形图

**数值轴是删除掉的**（`<c:delete val="1"/>`），所以既没有刻度标签也没有网格线。
另外华东那根柱子的数据标签被手工拖过——2563 那根柱子顶端在 y=267，而均值线
正好压在 258，按默认位置标签会和黄线重叠，作者把它拖到了线下方。

### 图 3 · 渐变圆角柱形图

柱子是**图片填充**：每个数据点 `<c:dPt>` 里是 blipFill，指向
`xl/media/image1~4.png`——四张 12px 宽的胶囊形渐变图，圆头已经烘焙在图里，
Excel 用 `a:stretch/a:fillRect` 把它拉伸进柱子矩形。柱顶那 6 个圆角标注框
和 6 根带头圆点的连接符都在 userShapes 里，框里数字则是数据标签被手工拖过去
的结果，绘制顺序是「标注框压在数据标签之上」。

### 图 4 · 标注柱形图

数据标签不是普通的「柱顶外侧数值」，而是**填充色跟着柱子走的气泡标注**
（45×26px 矩形 + 贴在矩形下边的三角尾巴）。XML 里只有 `manualLayout` 的
偏移小数、没有尾巴几何，所以矩形的 8 组位置、尾巴的底边与尖端、每个数字的
墨迹包围盒全部是实测的。

另外本机的 `calibri.ttf` 在 11.52pt（= 8pt × 1.44）这个尺寸上抗锯齿会渲染
成空白，脚本改用 `TextPath` 取字形轮廓 + `PathPatch` 填色绕开。

### 图 5 · 层叠柱形图

**两个系列是重叠的**（`overlap=30%`），不是并排：蓝柱真实宽 28.8px，被红柱
压掉 30% 只剩 20px 可见。由此引出两个坑：数据标签的 `outEnd` 对齐的是**柱子
本身（未被遮挡）的中心**而不是类别中心，两根柱心各偏离类别中心约 ±10px；
类别轴线画在柱子**之上**，所以 bottom spine 要抬 zorder。

图例也不是 Excel 图例，是 userShapes 里的两个描边文本框。

### 图 6 · 蝴蝶图（图表版）

横向堆积条形图 + 两条**完全透明的占位系列**：占位 1 是镜像公式（3453 − 值），
把蓝柱右端全部对齐；占位 2 恒为 1215，在中间留出固定宽度的空白带，类别名
就是这一系列的数据标签。红柱则从 4668 起画，左端全对齐。

### 图 7 · 蝴蝶图（单元格 REPT 版）

这张图**不是图表对象**，是单元格堆出来的：`=REPT("|", 数值*200)` 把竖线字符
重复成柱子，条子上的细密竖纹就是 Stencil 字体「|」的字形本身。长度 = 字符数
× 3.0px + 4px 前导，超出单元格可见宽度的部分被切齐（原图第 1、2 行的蓝柱就是
这么被切平的）。

它的误差明显高于其它图，原因是**参考图的文字带 ClearType 次像素抗锯齿**：
这张原图是用「复制单元格区域为图片」导出的，R-B 通道差平均 51、最大 156；
而其余 14 张是 Chart.Export 导出的图表对象，走的是灰度抗锯齿（R-B 差平均
12）。柱子的位置已经逐像素吻合（107~288 / 398~630 完全一致），差的是文字
笔画上的红蓝镶边，灰度渲染器复现不了。

### 图 8 · 数值百分比

三段堆积横条：深蓝（销量）+ 浅蓝（隐形占位）+ 暗红（恒 1080.25）。关键是
「销量 + 占位 = 4321」在六行上恒等，加固定 1080.25 后每条总长恒为 5401.25，
暗红段固定占右端 20%，所以百分比标签天然排成一条竖线。

### 图 9 · 对比柱形图

那根「差值箭头」是**折线系列 + 误差线**拼出来的：系列 1（浅蓝柱）挂一条
`errBars`（plus 方向、自定义值取 $E$3:$E$7、`tailEnd type="triangle"`），
于是浅蓝柱顶伸出一根带三角箭头的白线指到深蓝柱顶；折线系列本身线是 noFill，
只留一个 `symbol="picture"` 的图片标记（`image5.png`），在深蓝柱顶画出一条
60px 的深蓝细横线。箭头旁边的数字来自单元格区域而不是系列值
（`c15:datalabelsRange`）。

### 图 10 · 甘特图

同样是「隐形系列 + 误差线」：系列 0 填充 noFill，长度 = 开始日期，系列 1 用
`grouping=stacked + overlap=100` 接着它画；系列 0 的加号误差线宽 14.5pt、
长度 = 已完成天数，`00B0F0` 以 80% 不透明度盖在柱子上，把已完成部分染成浅蓝。
横向条形图的类别轴是**反向**的，第一类画在最上面。

### 图 11 · 平滑折线图

折线是平滑的（`c:smooth val="1"`）：Excel 的平滑 = 相邻点之间插一段三次贝塞尔，
控制点取「相邻两点的差向量 / 6」，也就是均匀参数化的 Catmull-Rom 样条，用
`Path.CURVE4` 逐段拼即可。绘图区下方那条年份色带不是坐标轴，是 userShapes 里
的两个圆角矩形。

### 图 12 · 菱形走势图

8 个类别各一条竖直细线升到数值处，顶端是**空心菱形标记**，上方是两位小数的
百分数标签。数值轴是 `delete="1"`。

### 图 13 · 对比折线图

双折线带实心圆点标记，图例在右上角。**六个数据标签被手工拖过**，位置存在
`c:dLbl/layout/manualLayout` 里，x 占图表区宽、y 占图表区高，叠在
`dLblPos="r"` 的默认锚点上。

### 图 14 · 单值圆环图

`holeSize=90`（即内半径 = 外半径 × 90%）、`firstSliceAng=300`，85% 的实心段
配 15% 的占位段（`bg1 lumMod95% alpha=10%`）。

**渐变方向是量出来的，不是算出来的。** XML 写的是线性 `ang=5400000`（自上而
下），但照这个方向铺，环上凡是同一高度的点颜色都该一样——实测却不是：圆环正
右方是实打实的紫，正左方却是玫红，两者 y 完全相同。所以脚本把原图沿一圈每
5° 采一个色写进色表，画的时候按角度插值。

### 图 15 · 水球图

画布上根本没有「水球」这个图形：chart14.xml 是一张只有一根柱子的柱形图
（`gapWidth=0` + `overlap=100`），两条系列叠在一起，填充都是 SVG 图片
（`image7.svg` 是实心圆、`image9.svg` 是空心圆环）；柱形图按 `stackScale`
把图片按整根柱高缩放再裁掉上部，于是系列 1 铺满变成内圈细环，系列 0 只露出
下面 65%，圆顶被水面切平——那条水平水面线就是切口。外圈更粗的环和圆心的
「65%」都在 userShapes 里。
